# API Conventions (@probable-futures/api - PostGraphile + Express)

GraphQL API generated by PostGraphile from the Postgres schema, served on Express. Postgres + PostGIS, Redis, Auth0/JWT, Sentry, pino.

## The schema is generated from the database

- Most API shape changes are **database migrations** (see `.claude/rules/db.md`), not resolvers. New tables/columns/views/functions are exposed automatically by PostGraphile.
- Add a **PostGraphile plugin** in `src/plugins/` only when the schema cannot express the logic (external calls, reshaping, custom auth). Use `makeExtendSchemaPlugin` with `gql` typeDefs + resolvers and register it in `src/plugins/index.ts`.

## Server structure (don't restructure for a feature)

- `src/main.ts` (bootstrap + Sentry) -> `src/app.ts` (middleware chain) -> `src/database.ts` (`rootPgPool` + `authPgPool`).
- Middleware are `installX(app)` functions in `src/middleware/`, exported from `index.ts`, invoked in order in `app.ts`. Add new ones the same way.
- Non-GraphQL endpoints are Express routes in `src/routes/<name>/` with `index.ts`, `parameters.ts`, `schema.json`. Integration logic goes in `src/services/` (mailchimp, ses, geocode, aws, donation, tracking).

## Auth

- `express-jwt` + JWKS validates Auth0 tokens, or an API key. Enforce the correct scope: `pfpro:manage`, `pfpro:read`, `pfpro:write`, `statistics:read`, `public:read`. The request maps to a Postgres role; row visibility is enforced by RLS, not app code.

## Config, logging, errors

- Config via `env-var` (`env.get("X").required().asString()`), loaded from `.env`. Never hardcode secrets or DSNs.
- Log via the shared pino logger / `extendDebugger("namespace")` - **never `console.*`**.
- Follow existing error handling (`errorUtils.serialize`, Slack notifier, installed error-handler + Sentry middleware). Don't leak SQL, stack traces, or internal IDs in responses.
- Sentry is initialized once in `main.ts` - don't add a second init.

## Tests

- `yarn workspace @probable-futures/api test` (`test:unit`, `test:integration`). Update/add tests for changed handlers, services, and plugins; cover success and failure paths.

## Prohibited

- No `console.*`. No hand-written resolver for something the Postgres schema can express. No hardcoded secrets/DSNs/URLs. No emojis.
